# 修改方案

## 修改概述

依据用户提供的 `../Spatial-DsRA v4.md`（V4.0），将 OpenVLA-OFT 和 π0 的 PyTorch Spatial Forcing 训练路径从固定单层对齐改为全层共享基方向级分配（SBRLA）。SLA 目录保留为方案 §6 的基线，不替换为 v4；原始不带空间蒸馏的训练入口和动作推理网络不增加空间分支。

核心实现严格采用：

```text
B_l = GELU(SharedLayerNorm(H_l) W_down + b_down)
pi = (1-epsilon) softmax(rho/T, dim=layer) + epsilon/L
R_l = diag(pi_l - 1/L)
B_fuse = mean_l(B_l) + sum_l((B_l M * (pi_l - 1/L)) M^T)
U_fuse = B_fuse W_up + b_up
Y = bilinear(Z) + E
L_total = L_action + alpha L_align(U_fuse,Y) + eta ||M^T M-I||_F^2
```

GELU 沿用原工程的激活函数作为方案中的 φ。没有加入逐层损失、输入依赖 gate、额外幅度/均衡正则。两个独立 Python 工程各有一份相同的核心模块，以避免跨工程导入依赖；两份内容已核对一致。

### 维度核对

| 节点 | OpenVLA-OFT | π0 | 核对依据 |
|---|---|---|---|
| 层数 L | 从 text_config 读取；标准配置 32 | 从语言模型 layers 读取；标准配置 18 | 不将 32 硬编码到 π0 |
| H_l | [B,N,4096] | [B,N,2048] | 实际宽度从模型读取；去掉 hidden_states[0] |
| 视觉 token | BOS 后的纯 patch；双视角通常 N=512 | prefix 开头的图像 patch；三视角通常 N=768 | 不包含 proprio、时间、语言、动作 token |
| B_l | [B,N,256] | [B,N,256] | 同一个 LN、down、GELU |
| M / Q_l | [256,32] / [B,N,32] | 相同 | 正交初始化，rank 不超过瓶颈维度 |
| rho / pi | [32,32] | [18,32] | softmax(dim=0)，每列跨层之和为 1 |
| 低秩修正与融合 | [B,N,256] | [B,N,256] | 对修正求和，不再除以 L |
| U_fuse / Y | [B,N,2048] | [B,N,2048] | VGGT frame/global 特征拼接为 2×1024 |

方案 §5 的 d_g=1024 是参数量示例；当前代码的 VGGT aggregator 实际输出为 `cat(frame, global, dim=-1)`，因此使用 d_g=2048，避免错误截断、额外投影或维度不匹配。标准 OpenVLA 辅助参数为 **1,592,576**（包含共享 LayerNorm 的 8192 个参数）；方案的参数量公式未计入 LN。

视觉层数、每层 [B,N,d_v]、融合/教师完整形状、有效 mask 的 [B,N] 与 bool 类型均在运行时校验。重采样验证每视角 token 数是平方数、教师 patch 数与网格一致；当前两种视觉骨干都使用方形 patch 网格。有效 token 采用全批有效 token 数归一化；全无效 mask 返回零对齐损失，正交项仍独立计算。

### 三阶段与配置

| 阶段 | 范围（优化器更新步） | 更新参数 | 冻结参数 |
|---|---|---|---|
| I | step < spatial_warmup_steps | 共享 LN/down/up、VLA LoRA、动作头 | rho、M |
| II | warmup ≤ step < absorption_start | 上述参数及 rho、M | VGGT |
| III | step ≥ spatial_absorption_start | VLA LoRA、动作头 | 全部辅助模块和 VGGT |

VGGT 始终 eval、requires_grad=False、no_grad。第三阶段仅改变辅助参数 requires_grad，不对 H_l/fused 特征 detach，也不把辅助前向放入 no_grad。两组优化器参数在冻结前注册，DDP 开启 unused parameter 检测并不使用 static_graph，以支持阶段切换。M/rho 的低学习率倍率在预热和衰减中保留。

以下四项文档没有给定数值，必须由实验配置显式提供，代码不会假定论文推荐值：

- `spatial_warmup_steps`：正整数。
- `spatial_absorption_start`：大于 warmup；若要实际执行 Stage III，应小于训练总步数。
- `spatial_orth_coeff`：eta，非负；0 可用于文档正交项消融。
- `spatial_basis_lr_scale`：相对于主学习率的倍率，严格位于 (0,1)。

其余初始值为瓶颈 256、rank 32、T=1、epsilon=0；OpenVLA 沿用原工程 alpha=0.5 配置，π0 沿用对应训练配置的 alpha。LoRA 默认 rank 32，仅作用于语言注意力 Q/V；π0 保留原动作 expert/head 的训练。旧 `vla_layers_align`、`use_vlm_norm`、`gain_feat_1move` 参数为接口兼容保留，v4 路径不使用它们进行单层选择、可选归一化或偏移切片。

### 教师对应、缓存与推理

OpenVLA 由送入学生的同一批 pixel_values 反归一化构建教师图像，包含同一次图像增强；π0 原有 `get_wo_aug=True` 路径已经禁用几何裁剪/旋转，保留原有 padding mask。教师特征按原相机顺序逐视角插值，随后在目标网格加现有正弦位置编码（沿用原实现 E 的 0.1 缩放）。

本次交付范围是模型及训练接入，使用现有在线冻结 VGGT 路径；未生成数据集离线缓存。方案 §3.2 允许固定数据集离线缓存，但仓库没有随任务提供实际数据/教师权重，无法执行 §4 Stage 0 的离线特征提取。若后续使用缓存，必须保持图像增强、视角顺序和 token 网格对应。

OpenVLA 沿用既有辅助模块 checkpoint 保存方式；旧 SF projector 的权重结构与新模块不兼容，不能作为 v4 辅助 checkpoint 直接恢复。π0 checkpoint 新增 `spatial_dsra.pt` 和 `training_model.pt`，分别保存辅助模块与未合并 LoRA 的完整训练模型；`model.safetensors` 导出合并 LoRA 后的基座键名，供原推理网络加载。恢复训练需要 v4 新格式，阶段由恢复的 global_step 和相同配置重建。OpenVLA 原训练器不保存优化器状态的既有行为未扩展为精确断点续训。
